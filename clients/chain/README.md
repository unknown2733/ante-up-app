# Chain client boundary (fixture slice)

`idl/ante_up.json` was generated by `anchor idl build` from the Rust program.
`src/generated/` was generated from that IDL with Codama's Kit renderer;
`npm run generate` reproduces it. `npm run check`, `npm run build`, and `npm test`
run the client checks. The program ID remains a deterministic fixture
placeholder with no matching keypair. The package supplies instruction and
account codecs but does not make fixture transactions executable on Devnet.

## Consumer API

The package entry `src/index.ts` exports the generated Kit client and these
stable aliases/helpers:

| Consumer | API | Meaning |
| --- | --- | --- |
| D transaction preparation | `buildOpenFreeInstruction`, `buildCloseFreeInstruction`, `buildPublishSnapshotInstruction` | Typed Kit instructions; wallet/server still assembles, checks, signs and submits the transaction. |
| D indexer | `decodeAnteUpEvent(rawBytes)` | Typed `freeOpened`, `freeClosed`, `proofCompleted`, `snapshotPublished` event payload. Input must be extracted from this program's invocation in a finalized transaction. |
| D current reads | `fetchFinalizedFreeRecord`, `fetchFinalizedMarket`, `fetchFinalizedSnapshot` | Finalized account state only. Generated `decodeFreeRecord`, `decodeMarket`, `decodeSnapshot` also accept already fetched encoded accounts. |
| D/F identity | `findMarketPda`, `findSnapshotPda`, `findRecordPda`, `ANTE_UP_PROGRAM_ADDRESS` | Fixture account mapping; cluster must be supplied externally. |

## Executable Kit runtime

`src/runtime.ts` is also exported from the package entry. It keeps the
generated builders above intact. `createKitChainTransport(endpoint)` uses
finalized Kit RPC account reads and accepts no credential itself. Callers may
inject a `ChainTransport` instead for deterministic tests or a controlled RPC
proxy. `readFinalizedConfig`, `readFinalizedAdmission`, `readFinalizedMarket`,
`readFinalizedSnapshot`, and `readFinalizedFreeRecord` check the derived
address, program owner, and the account's stored identity where applicable.
The market ID used to derive the Market PDA is a separate **32-byte registry
seed**. The `marketAddress` used in Snapshot/FreeRecord and wire records is
that Market PDA in base58, never the keyword or registry seed.

The six `create*Instruction` functions cover `initialize`, `registerMarket`,
`publishSnapshot`, `openFree`, `closeFree`, and `completeProof` using the
compiled IDL's generated async builders. They use Kit no-op signers solely to
mark required signer accounts in unsigned instructions. The caller provides
real signing only at submission. `registerMarket` returns `marketAddress`;
`publishSnapshot` returns `snapshotAddress`; open/close/proof return
`recordAddress` beside `instruction`.

```ts
import {
  createKitChainTransport, createOpenFreeInstruction,
  prepareUnsignedTransaction, submitAndConfirmFinalized, withKitSigner,
} from '@ante-up/chain-client';

const transport = createKitChainTransport(rpcEndpoint);
const {instruction, recordAddress} = await createOpenFreeInstruction({
  marketAddress, owner: wallet.address, recordId,
}, deployedProgramAddress);
const prepared = await prepareUnsignedTransaction({
  transport, instruction, feePayer: wallet.address,
  programAddress: deployedProgramAddress,
});
// A wallet or injected Kit partial signer supplies the signature. The helper
// compiles the expected instruction again before it signs or sends.
const result = await submitAndConfirmFinalized({
  transport, prepared, expectedInstruction: instruction,
  sign: withKitSigner(wallet.partialSigner),
});
// Only result.state === 'FINALIZED' proves finalized success.
```

`prepareUnsignedTransaction` fetches a recent blockhash and returns canonical
base64 wire bytes plus payer, program and expiry metadata. The submit helper
rejects a changed instruction, payer, program, message, signature set, or
invalid/expired blockhash before sending. It sends once and reports
`FINALIZED` only after an error-free finalized signature status. An RPC send
exception, lost status, signature mismatch, or expired unfinalized transaction
returns `UNKNOWN` with the signed signature when available. The caller should
reconcile that signature before deciding to retry. `FAILED` means RPC
reported a transaction error. Injected transports in tests do not prove
program execution on a chain. The current program address is still a fixture
placeholder without a corresponding deployment keypair.

The indexer attaches `(cluster, programId, signature, eventIndex)` to each
decoded event, using the actual transaction slot/order/finality from RPC.
`FreeOpened` now carries the executed entry point; `FreeClosed` carries both
points, terminal result and N/A reason. `ProofCompleted` carries the record
identity and proof hash. This lets replay reconstruct an immutable result
without reading the mutable FreeRecord account at a later time. A current
account read is a snapshot of **now**, never evidence of a past event's exact
state. `SnapshotPublished` identifies a separately immutable snapshot account;
the indexer checks its market/sequence/hash against the event and transaction
before admitting it as a published price. The event payload has no signature
or finality field; RPC supplies them.

## PDA seeds (all byte strings, little endian u64)

| Account | Seeds | Writer |
| --- | --- | --- |
| Config | `"config"` | admin initialization/config gate |
| Admission | `"admission"` | free open/proof complete; admin gate |
| Market | `"market"`, 32-byte normalized market ID hash | admin register/publisher snapshot |
| Snapshot | `"snapshot"`, market pubkey, sequence u64 LE | publisher only |
| WalletStats | `"free-wallet"`, owner pubkey | owner free open/close |
| WalletMarket | `"free-slot"`, owner pubkey, market pubkey | owner free open/close |
| FreeRecord | `"free"`, market pubkey, owner pubkey, record ID u64 LE | owner open/close; proof authority complete |

`market_id` should be a domain-separated SHA-256 of the canonical normalized
market identity; the exact preimage format needs A integration approval before
live use. Record ID is client-chosen per wallet/market and PDA uniqueness rejects
replay. The raw `payload_hash` is the A canonical JSON hash supplied by the
publisher; the program binds it to stored typed fields but cannot recompute the
off-chain canonical JSON payload. Consumers must compare both the stored hash
and fields against the finalized candidate before accepting a price.

Contract revision 0.2 keeps wire schema 0.1. `clients/chain/encoding.mjs`
strictly decodes lower-case 64-digit hex `queryHash`/payload/evidence hashes to
32 bytes and encodes `h3-d7-q12-v1` as 12 ASCII bytes plus four zero bytes.
The program rejects every other formula byte sequence. Snapshot input also
contains the candidate's query hash and trading admission state; `OPEN` is
accepted only with valid data and recovery count 0 (bootstrap) or 2, and
`RECOVERING` only with count 1. The program cannot prove that C's count came
from distinct regular poll batches, so publisher authentication remains
essential. Trading admission is separate from the free-chip admission gate.

## Intended call order

1. `initialize` once with admin, publisher, proof authority and a fixed 16-byte
   formula version. The first signer becomes admin, so deployment must bind
   initialization to the intended operator in its controlled transaction.
2. `register_market` once per market ID; a duplicate PDA init fails atomically.
3. `publish_snapshot` with the next sequence and the current query/config
   version. The account is immutable after creation; `Market` points to it.
4. An operator raises `funded_open_cap` only after reserving the proof budget
   for every unused lifetime admission, then opens the free admission gate.
   `open_free` atomically increments `funded_open_count` in addition to the
   global and per-wallet 24-hour rings, concurrent counts, per-market slot,
   and outstanding proof duty. Direct program calls face the same cap.
5. `close_free` is owner-signed and permitted regardless of the gate or data
   outage. It releases the concurrent slot and stores an immutable numeric or
   N/A result. It does not restore a spent funded admission or release the proof duty.
6. `complete_proof` is proof-authority-signed after the external verifier has
   checked storage contents, 20 confirmations, and SAS issuance. It releases
   the outstanding duty exactly once. This first slice does not implement that
   verifier; the authority must keep the gate closed in any real environment.

## Permissions and missing asset path

The admin controls registration and the intake gate. The publisher alone
posts snapshots. Owners alone open and close their free records. Proof
authority alone marks evidence completion. Upgrade authority and admin key
rotation need a separate deployment runbook.

The financial instructions use classic SPL Token accounts for minting, custody,
curve and spot trades, Pro collateral/claims, and LP deposits/redemptions.
`ante_up_math::Ledger` remains a pure reference transition model; the program
reads actual token balances and applies checked token CPIs.

## Financial IDL integration

The committed Anchor IDL and Codama output now expose
`getInitializeFinanceInstructionAsync`, `getConfigureFaucetInstructionAsync`,
`getClaimFaucetInstructionAsync`, `getRegisterFinancialMarketInstructionAsync`,
`getCurveBuyInstructionAsync`, `getCurveSellInstructionAsync`,
`getGraduateInstructionAsync`, `getSpotBuyInstructionAsync`,
`getSpotSellInstructionAsync`, `getOpenProInstructionAsync`,
`getCloseProInstructionAsync`, `getAcceptSettlementInstructionAsync`,
`getSettleProInstructionAsync`, `getClaimProInstructionAsync`,
`getStartLpWindowInstructionAsync`, `getDepositLpInstructionAsync`, and
`getWithdrawLpInstructionAsync`. Generated `findFinanceConfigPda`,
`findFinanceMarketPda`, `findKeywordMintPda`, `findCurveInventoryPda`,
`findVaultInventoryPda`, `findPaymentVaultPda`, `findReceiptPda`,
`findPositionPda`, `findClaimPda`, and `findHoldingPda` derive
the relevant accounts. `readFinalizedFinanceConfig` and
`readFinalizedFinanceMarket` verify finalized account owner, PDA,
discriminator and market identity. The financial register instruction creates
the Market PDA and its token mint/accounts in one transaction, charging 10
tUSD only on success; the older admin-only `registerMarket` remains available
for the existing free path.

The payment mint must already exist with six decimals and mint authority set
to the `finance-config` PDA. The protocol treasury and caller-owned token
accounts must be initialized classic SPL Token accounts. The keyword mint
receives 2000 tokens once and has its mint authority revoked. All quantities
are six-decimal atoms. Curve and graduation instructions bind the latest
snapshot sequence, config version, finance state version and a deadline no
more than 30 seconds away. The generated builders encode these fields; the
on-chain handler rechecks them. `marketId` in the register builder is a
32-byte registry seed. Financial wire `marketAddress` remains its PDA.

The settlement account is keyed by `(marketAddress, FinanceMarket.currentCycle)`.
Use `findSettlementPda(marketAddress, cycle, programAddress?)` from the public
runtime export and pass the address explicitly to close, accept, settle, and
LP-window instructions. Cycle zero is valid for an empty initial cycle.

The financial LiteSVM test seeds a local tUSD mint and funding accounts, then
executes faucet, registration, curve, graduation, spot, Pro, settlement, claims,
and LP transfers through the compiled SBF program and classic SPL Token CPI.
It runs with `ANTE_UP_SBF_PATH` on Linux; without an SBF binary it is skipped.
Host compilation, IDL generation and Kit serialization alone do not establish
that real token movement succeeds. No Devnet transaction has been executed.
