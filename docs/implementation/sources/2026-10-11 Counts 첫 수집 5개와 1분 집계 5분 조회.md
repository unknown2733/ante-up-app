# Counts 첫 수집 5개와 1분 집계 5분 조회

## 맥락

[영어 키워드 집계 규칙](<2026-10-11 영어 키워드 Counts 집계 규칙 채택.md>) 채택 후 첫 대상 수·원자료 집계 단위·조회 주기와 비용을 비교했다. 사용자가 직전 추천 조합을 채택했다.

## 결정

> 첫 상시 수집은 영어 키워드 5개로 시작한다. 원자료는 1분 단위로 저장하고, 5분마다 새 구간들을 일괄 조회한다. 짧은 라이브 데모에서는 1분 조회를 별도로 적용할 수 있다.

- 기본 설정: 대상 5개, `granularity=minute`, 5분 조회.
- 시간순으로 1분 관측을 EWMA에 반영하고 같은 구간을 중복 가산하지 않는다. 5분 조회를 1분 실시간 제공으로 표시하지 않는다.
- 1분 조회는 데모용 선택지로 허용하며 항상 켜는 기본값이나 실행 일정으로 정하지 않는다.
- 이 수는 초기 연동·검증 대상 수다. 자유 등록 제품의 영구 시장 수 상한이 아니다.
- 구체 키워드·별칭 목록·과거 이력 길이·초기값·EWMA 반감기·비교 간격은 이번 결정에 포함하지 않는다.

## 이유

- 활동 패턴을 비교할 수 있는 대상 수를 확보하면서 상시 호출 비용을 통제한다.
- 분별 원자료를 보존해 이후 지표와 집계 간격을 재검토할 수 있다.
- 원자료 해상도와 API 호출 빈도를 분리한다.

## 검토한 대안

- 3개: 더 저렴하나 활동 패턴 비교가 제한된다.
- 10개: 첫 연동 단계에서 비용과 관찰 범위가 커진다.
- 상시 1분 조회: 기본안 대비 호출 비용이 5배다. 짧은 데모에 선택적으로 사용한다.
- 15분 조회: 짧게 이용하는 사용자가 새 관측을 확인하기 어렵다.

## 영향

- 2026-10-11 공식 Recent Counts 요청당 $0.005 기준, 5개·5분은 하루 $7.20 / 30일 $216이다. 24시간 운영·키워드별 1요청/조회 가정이며 이력·재조회·서버·오라클 비용은 별도다.
- 설정 채택은 실제 유료 수집을 지금 시작하거나 자동 충전·지출 상한을 설정하라는 지시로 확대하지 않는다. 이번 작업은 기록과 다음 결정 검토다.
- 이 결정 당시 다음 검토는 초기 이력·초기화였다. 후속 [과거 28일 선조회와 EWMA 초기화](<2026-10-11 과거 28일 선조회와 EWMA 초기화.md>)를 사용자 승인으로 채택했다. 반감기·비교 간격·구체 초기값은 계속 미정이다.
- 변경 문서: HOME, 핵심 결정과 비교 기준, LP 자산과 외부 관심지수의 연결 설계.
- 재검토 조건: 실제 API 지연·비용·활동량이 시연 경험과 맞지 않거나 수집 시장 수를 확대할 때. 재검토 기한은 미정이다.
