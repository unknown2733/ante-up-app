# EWMA 반감기 3일과 비교 간격 7일

## 맥락

[과거 28일 초기화](<2026-10-11 과거 28일 선조회와 EWMA 초기화.md>) 이후 반감기와 비교 간격의 1/3/7일 조합을 합성 두쫀쿠 데이터로 비교했다. 사용자가 H=3일, D=7일을 선택했다.

## 결정

> 영어 키워드 MVP의 EWMA 반감기를 3일, 현재 평활 활동 지표와 비교할 과거 시점의 간격을 7일로 정한다.

- 반감기는 실제 경과 시간에 적용한다. 1분 집계와 5분 조회를 유지하고 새 관측을 시간순으로 반영한다.
- 7일 전 동일 시점의 EWMA와 비교하는 방향이다. 7일마다 한 번 가격을 갱신하거나 7일 만기·정산을 채택하는 의미가 아니다.
- 과거28일 초기화·필요시 이력 보강, 주중 갱신·주간 가격 이월 방향은 유지한다.
- 초기 seed·최소 활동량·준비 완료 기준·최종 가격 연결과 상한 적용은 다음 결정이다.
- 이 선택을 실제 데이터로 최적화된 수치나 보호형 거래의 지급 안전성 검증으로 해석하지 않는다.

## 이유

- 며칠간의 새 활동을 반영하면서 지난주와의 관심 추세 차이를 보여주는 설정이다.
- 7일 반감기보다 반응이 빠르고, 1일 비교보다 오래된 기준과의 차이를 유지한다.
- 합성 재유행 예시의 큰 상승·하락 가능성을 확인한 상태에서 초기 설정으로 채택했다.

## 검토한 대안

- 1일/1일, 7일/7일, 3일/3일은 비교 이력으로 보존하며 현재 기본 설정으로 채택하지 않는다.

## 영향

- 일반 재귀 EWMA의 1분 감쇠계수는 q=2^(-1/4320), 새 관측 가중치는 1-q다. 5분마다 전체 관측을 한 점으로 처리하지 않는다.
- 이 결정 당시 하루 평균 초기값은 제안이었다. 후속 [본딩커브 데이터 병렬 진행과 하루 평균 초기값](<2026-10-11 본딩커브 데이터 병렬 진행과 하루 평균 초기값.md>)에서 가장 오래된24시간 끝을 초기화 시점으로 하고 나머지27일을 재생하는 방식을 채택했다.
- 최소 활동량과 준비 완료 기준에 대한 다음 제안도 아직 미채택이다.
- HOME, 핵심 결정 문서, 연결 설계에 반영한다. 유료 API 수집·계약 구현·배포는 이번 작업에서 실행하지 않았다.
- 재검토 조건: 실제 데이터의 희소성·지연·움직임이 의도한 경험과 맞지 않을 때. 기존 포지션에 설정 변경을 소급 적용하는 규칙은 정하지 않았다.

## 근거

- 사용자 직접 선택, 2026-10-11 현재 대화.
- 직접 인용: “좋아. 그러면 일단 반감기 3일, 비교 간격 7일로 픽스하고 기록해줘. 다음으로 초기값이랑 최소 활동량, 준비 완료 기준을 어떻게 정할지 예시랑 함께 정리해보자.”
- 영구 메시지 ID는 제공되지 않았다. 관련 비교는 [핵심 결정 문서](<../20_Working/관심 선택 제품의 핵심 결정과 비교 기준.md>)와 [.codex-work/ewma-parameters/simulate.cjs](<../.codex-work/ewma-parameters/simulate.cjs>)에 보존한다.
