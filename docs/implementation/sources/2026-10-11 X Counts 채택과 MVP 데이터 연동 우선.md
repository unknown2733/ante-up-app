# X Counts 채택과 MVP 데이터 연동 우선

## 맥락

영어 키워드의 실제 활동을 [EWMA](<2026-10-11 EWMA 활동 지표 방향 채택.md>)에 연결할 데이터 소스를 검토했다. Counts 조회 주기, 집계 지연·수정, 호출 한도·비용과 더 빠른 데이터 보유자가 오래된 가격을 이용할 가능성을 논의했다. 사용자는 현재 MVP에서 실제 데이터 수집·반영을 우선하고 가격 지연을 이용한 거래 방어는 후속으로 미루기로 선택했다.

## 결정

> 영어 키워드 MVP의 데이터 소스로 X Counts를 사용한다. 실제 데이터 수집 → 저장·계산 → 화면 반영 → 칩의 진입·종료 기록을 먼저 완성하고, 오래된 가격을 이용하는 거래에 대한 방어와 체결 고도화는 후속으로 다룬다.

채택한 우선순위:

| 단계 | 우선 완성할 내용 |
|---|---|
| P0 | 키워드 검색 조건에 따른 실제 Counts 조회, 구간별 값·수집 시각 저장, 수집 성공·오류 상태 확인 |
| P1 | 신규 관측의 EWMA 반영, 동일 구간 중복 가산 방지, 결측과 실제 0 구분, 실제 경과 시간에 따른 감쇠, 계산 근거·설정 버전 보존 |
| P2 | 원천 활동량·EWMA 지표·마지막 갱신 시각·내 칩의 변화·종료 결과를 제품에 연결 |
| P3 | 키워드 선택 → 실제 데이터 확인 → 칩 걸기 → 이후 변화 확인 → 거두기 → 당시와 종료 결과 확인의 경로 완성 |

- 실제 주중 갱신, 주간 가격 이월·권리 연속성, 무료 기록/선택적 금전 참여와 기본/Pro 모드 방향은 유지한다.
- 구체 파라미터가 미정이어도 명시적으로 임시 설정을 사용하는 데모를 구성할 수 있도록 설정·산식 버전을 분리한다. 임시값을 최종 가격·계약 결정으로 취급하지 않는다.
- 거래 방어를 미뤄도 중복·결측 처리와 관측·계산 이력 보존은 이번 단계의 기본 요구사항으로 남긴다.

## 이유

- 데이터부터 사용자 결과까지 실제로 이어지는지 먼저 확인한다.
- 최종 체결·지급 설계가 모두 끝나야 데이터 연동을 시작할 수 있는 의존성을 없앤다.
- 이후 정책을 바꿀 때 비교할 수 있도록 실제 관측과 계산 근거를 남긴다.

## 검토한 대안

- 가격 지연 방어·복잡한 정정 정책을 먼저 완료: 현재 MVP 우선순위로 선택하지 않는다.
- Filtered Stream을 먼저 도입: 이번 데이터 경로는 Counts로 선택하고 Stream은 후속 후보로 유지한다.
- 모든 데이터 오류 처리를 나중으로 유보: 중복 가산·결측의 0 처리 등 기본 계산 오류는 현재 단계에서 방지한다.

## 영향

- 후속 2026-10-11 [영어 키워드 집계 규칙](<2026-10-11 영어 키워드 Counts 집계 규칙 채택.md>)을 채택해 검색 의미를 구체화했다. 아래 ‘다음 선택’은 이 결정 당시 목록이며 대상 수·집계/조회 주기·이력·EWMA 등의 미정 범위는 계속 남는다.

- 변경 문서: HOME, [핵심 결정과 비교 기준](<../20_Working/관심 선택 제품의 핵심 결정과 비교 기준.md>), [연결 설계](<../20_Working/LP 자산과 외부 관심지수의 연결 설계.md>).
- 데이터 공급자 미정 중 이번 영어 키워드 MVP의 Counts 선택만 해소한다. 과거 결정의 나머지 범위는 유지한다.
- 다음 선택: 검색·언어·구문·별칭·리포스트 조건, 첫 대상 수·조회/집계 주기·비용 한도, 과거 이력·초기값, 임시 EWMA와 표시 지표, 칩 결과·SAS·온체인 연결 범위.
- 1분 조회, 키워드 5개, 72시간 실험, 반감기·비교 간격·최종 가격식·특정 오라클·비용 지출은 채택하지 않았다. 앞선 수량·기간·요금 계산은 제안 또는 조사 예시다.
- 후속: 오래된 가격 이용 방어, 주문/체결 버전·지연, 정교한 관측 확정·수정 정책, Stream 병행·대규모 운영, 보호형 거래·볼트 지급 안전성.
- 실데이터 연동의 성공을 경제적 안전성·실자금 거래 개방 승인으로 해석하지 않는다. 첫 데모의 Devnet/시뮬레이션/실자금 경계도 별도 결정이다.
- 이번 작업은 결정 기록과 문서 정렬이며 API 호출·구현·유료 실험·배포를 수행한 것은 아니다. 실행 Task나 일정 생성은 요청 범위에 없다.
- 재검토 조건: 실제 접근 권한·비용·지연·집계 의미가 MVP 요구를 충족하지 못하는 경우. 별도 재검토 기한은 미정이다.

## 근거

- 결정 주체: 사용자 직접 선택, 2026-10-11 현재 대화.
- 직접 인용: “Counts를 사용한다고 했을 때, 데이터를 먼저 본 사람이 오래된 가격으로 진입해서 수익을 가져가는 문제는 나중에 픽스하는걸로 하고, 일단은 mvp단계에서는 실제로 데이터를 풀링해와서 반영하는것까지에 집중하는걸로 했으면 좋겠는데, 우선순위를 정리해봐”
- 후속 승인·기록 지시 직접 인용: “좋아 이렇게 픽스할게. 반영해서 기록해주고, 남은 결정사항들 다시 브리핑해줘”
- 영구 메시지 ID는 제공되지 않았다. 현재 대화의 해당 두 발언과 그 사이 우선순위 제안을 승인 범위로 삼는다.
- 참고한 공식 문서: [Counts](https://docs.x.com/x-api/posts/counts/introduction), [호출 한도](https://docs.x.com/x-api/fundamentals/rate-limits), [요금](https://docs.x.com/x-api/getting-started/pricing). 조사와 실측을 구분하며 계정의 실제 권한·지연·수정 폭은 미검증이다.
