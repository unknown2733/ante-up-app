# 과거 28일 선조회와 EWMA 초기화

## 맥락

[5개·1분 집계·5분 조회](<2026-10-11 Counts 첫 수집 5개와 1분 집계 5분 조회.md>) 이후 과거 이력 없이 시작, Recent 7일 선조회, Full-archive 28일 선조회와 보강을 비교했다. 사용자는 직전 요약의 초기화 방식을 채택했다.

## 결정

> 키워드 등록 시 고정한 검색 조건으로 이전 28일의 1분 단위 활동량을 먼저 조회한다. 과거부터 현재까지 시간순으로 EWMA를 계산한 뒤 5분 주기의 새 관측을 이어 붙인다. 반감기·비교 간격을 정한 뒤 이력이 부족하면 추가 조회한다.

- 과거 데이터 조회는 새로 28일 동안 기다리는 의미가 아니다.
- 등록·주간 전환 때문에 EWMA 상태를 0으로 초기화하지 않는다.
- 28일은 초기 수집 분량이다. 28일 고정 계산 창·일괄 삭제·정산 주기를 채택하지 않는다.
- 등록 이전 데이터는 초기 상태와 비교 기준을 만드는 데 사용한다. 사용자에게 진입 이전의 성장 수익이나 과거 선택 기록을 소급 부여하지 않는다.
- 이력이 부족한 대상도 등록·무료 기록은 허용한다. 비교 근거가 부족하거나 분모가 0이면 성장률을 임의로 만들지 않고 준비 중으로 표시한다.
- 구체 초기 seed, 준비 완료 기준·최소 활동량, 금전 거래 개방 기준은 반감기·비교 간격 및 계약 설계와 함께 후속 결정한다.

## 이유

- 등록 당시 이미 존재하던 관심의 수준과 추세를 반영한다.
- 0 초기화로 생기는 인위적인 상승을 줄인다.
- 신규 키워드의 발견 기록과 계산 가능한 성과의 제공 시점을 구분한다.

## 검토한 대안

- 등록 이후부터만 수집: 이번 기본 초기화 경로로 채택하지 않는다.
- 최근 7일만 고정: 긴 반감기·비교 간격에 부족할 수 있어 기본 경로로 채택하지 않는다.
- 28일이면 언제나 충분하다고 간주: 채택하지 않는다. 설정에 맞춘 추가 이력 조회를 허용한다.

## 영향

- 이 결정 당시 다음 선택은 반감기·비교 간격이었다. 후속 [반감기3일·비교7일](<2026-10-11 EWMA 반감기 3일과 비교 간격 7일.md>)을 채택했다. 구체 seed·최소 활동량·준비 완료 수치는 계속 미정이다.
- 이력 조회와 상시 조회 사이의 같은 버킷을 중복 반영하지 않고, 정상 0과 결측을 구분한다는 기존 원칙을 유지한다.
- API 호출·유료 실행·실거래는 이번 기록 작업에서 수행하지 않았다.
- 재검토 조건: 실제 이력 접근·누락·초기값 민감도가 데모와 지표 계산에 부적합할 때. 재검토 기한은 미정이다.
- HOME, 핵심 결정 문서, 연결 설계에 반영한다.

## 근거

- 사용자 직접 선택, 2026-10-11 현재 대화.
- 직접 인용: “좋아. 그러면 이 방식으로 일단 픽스하고 기록해줘. 다음으로 EWMA 반감기랑 비교 간격을 어떻게 설정할지 두쫀쿠 예시로 선택지별로 비교해보자.”
- 승인 대상은 직전 요약의 과거 28일 조회→시간순 EWMA 초기화→새 관측 연결→필요시 이력 보강 및 이력이 부족한 대상의 준비 중 처리다. 영구 메시지 ID는 제공되지 않았다.
