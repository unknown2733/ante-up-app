# Arweave 5분 업로드와 20확인 완료 채택

## 결정

- 업로드B: 시장 공통 근거는 기존5분 검증 배치에 맞춰 비동기 업로드한다. 수집 즉시 원자료/해시를 재시도 가능한 큐에 보존한다. 초기 이력·규칙은 준비 시 별도 저장하고 재사용한다. 개인 결과는 종료finalized 후 다음5분 작업에 넣는다.
- 참조ID가 준비되지 않았다면 고정된 결과를 보존하고 근거 참조를 기다린다. 새 관측/정정본은 별도 버전으로 추가한다.5분은 작업 주기이며 보관/발급 완료시간 보장이 아니다.
- 보관완료③: 개인 결과 명세와 필요한 모든 공통 근거에 대해 저장ID·버전 확인, 실제 파일 조회·원본 SHA-256 일치, Arweave 체인 포함, 포함 거래20 confirmations 이상을 확인한 뒤 자동 SAS를 발급한다.
- 번들 경로는 해당 data item과 부모 L1 거래의 포함 관계를 확인한 후 부모 거래의 확인 수를 검사한다. 파일 하나/명세만 완료됐다고 전체 결과 근거를 완료로 간주하지 않는다.
- 접수 영수증·파일 조회·체인 포함/확인 수·SAS 발급 완료를 구분한다. 사용한 영수증은 허용한 서비스 키와 해당 버전 규칙으로 검증한다. SAS는 자체 Solana 거래 확정 후 완료로 표시한다.
- 업로드/체인 확인 대기는 가격 게시·무료 종료·슬롯 반환을 지연시키지 않는다. 원자료를 큐에조차 보존할 수 없는 상황의 신규 처리 규칙은 별도 검토한다.
- 오래 기다렸다는 이유로 완료 기준을 완화하지 않는다. 재시도는 같은 내용과 기록 참조를 유지하며 기존 접수 상태를 확인해 중복 업로드/지출을 줄인다.

## 범위와 영향

20확인은 프로젝트 MVP 정책값이다. 공식 필수값·절대 finality·20분 보장을 뜻하지 않는다. 소스 수집/가격 게시 주기를 변경하지 않으며 API 장애의24시간 비상 정산 규칙을 저장 장애에 적용하는 결정도 아니다.

Solana Devnet과 Arweave 저장 환경은 구분하며 저장sandbox 성공을 실제 Arweave20확인으로 표시하지 않는다. 업로더/신뢰할 포함 검증 경로·환경/비용·실패 대기·큐 한도·정정/무효 상세는 남아 있다. 실제 업로드/지출/배포는 미실행이다. 실제 지연과 운영 부담 검증 후 필요하면 정책을 명시적으로 재검토한다.

## 근거

사용자 직접 발언: “추천대로 픽스할게. 다음 결정사항으로 넘어가자”. 직전 응답의 업로드B+완료③ 및20확인 제안을 승인했다. 영구 메시지 링크/fragment ID는 제공되지 않았다.

비교 근거: [Turbo receipt](https://docs.ar.io/build/upload/receipts/), [파일 검증](https://docs.ar.io/build/upload/upload-and-verify/), [Arweave 상태API](https://docs.arweave.org/developers/arweave-node-server/http-api).20 자체는 이 문서들이 요구한 수치가 아닌 프로젝트 선택이다. [후속 검토](<../20_Working/관심 선택 제품의 핵심 결정과 비교 기준.md>).
