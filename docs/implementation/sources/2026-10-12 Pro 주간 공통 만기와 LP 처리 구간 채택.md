# Pro 주간 공통 만기와 LP 처리 구간 채택

## 맥락

[LP N3·L1](<2026-10-12 LP 지급 확정 시점 평가와 동순위 손익 채택.md>)에 따라 열린/가격 미확정 Pro가 없을 때 LP 지분을 발급·상환한다. 계속되는 신규 개설 때문에 이 시점이 사라지지 않도록 테스트넷 MVP의 계약·LP 운영 구간을 정한다.

## 결정

| 항목 | 채택 내용 |
|---|---|
| 정상 만기 | 매주 월요일 09:00 KST / 00:00 UTC 공통 만기 |
| 신규 개설 마감 | 만기 30분 전인 월요일 08:30 KST부터 신규 Pro 개설 중단 |
| 기존 종료 | 원만기 전에는 기존 데이터·계약 조건을 충족하면 전량 종료 가능 |
| LP 처리 | 모든 Pro 지급액이 확정되고 현재 유효한 NAV를 산정할 수 있게 된 뒤 최소 15분의 LP 처리 기회 확보 |
| 다음 주기 | LP 구간 종료 후 데이터·활동량·담보 조건을 확인하고 신규 Pro 개방 |
| 재진입 | 자동 갱신 없음. 새 진입가격·비용·담보 검사와 사용자 확인으로 새 계약 개설 |
| MVP LP 운영 | 정기 LP 구간 및 최초 Pro 개설 전 자본 형성 단계에서 지분 발급·상환 |

- 모든 진입에 7일을 보장하지 않는다. 다음 공통 만기까지의 실제 잔여기간과 비용을 견적에 표시한다. 시간·보호 비용의 구체적인 산식은 후속 결정이다.
- 만기 시점에 가격 노출이 끝나고 그 시점의 데이터로 평가한다. 복구가 늦었다고 복구 시점 가격으로 정상 만기 정산을 대체하지 않는다. 장기 장애 시에는 기존 공통 비상 정산 규칙을 적용한다.
- 정산이 09:15에 준비되면 LP 09:15~09:30, 09:40에 준비되면 09:40~09:55가 예시다. 정산 완료 시각을 보장하는 숫자가 아니다.
- LP 15분은 만기 후 정산 검증 대기시간과 별개다. **정산 검증 15분·일반 데이터 정정 마감 24시간은 아직 미채택**이다.
- LP 요청은 지분 권리·현재 NAV·가용 자산을 검사해 전액 처리하거나 거절/재요청한다. 자동 대기열·지분 발급 전 선입금은 도입하지 않는다. 초기 지분 개인 출금 잠금은 유지한다.
- LP 구간에도 현물 거래는 유효 데이터와 거래 한도 안에서 가능하다. 매 실행 시 현재 가격·잔고·외부 토큰 수량·확정 미지급 의무로 NAV와 가용 자산을 다시 계산한다. 만기 당시 가격으로 LP 구간 전체를 고정하지 않는다.
- 확정 후 아직 지급하지 않은 정산금·환급금은 지급까지 부채와 예약에 남긴다. 예약 해제가 곧 수익은 아니다.
- 주간 만기는 토큰 가격·현물 보유·무료 기록을 초기화하지 않는다. EWMA 반감기 3일·비교 간격 7일·5분 조회도 유지한다.
- 장애 중 LP 평가는 중단한다. 24시간 장애 기산과 원만기·비용 종료 규칙은 유지하며 LP 일정 때문에 기한을 다시 세지 않는다. 비상 정산금 확정만으로 현재 현물 가격이 복원되는 것은 아니므로 LP 개방은 더 늦어질 수 있다.

## 이유와 제약

대부분의 주중에 신규 진입·중도 종료를 허용하면서 정기적인 LP 평가 기회를 만든다. 늦게 진입하면 보호 기간이 짧고, LP 기회가 주 1회이며 데이터 장애로 지연될 수 있다는 제약을 수용한다. 30분 마감은 MVP 운영 기준이며 최적값·MEV 방어를 검증한 결과가 아니다. LP 처리 기회는 출금할 자산의 충분함을 보장하지 않는다.

## 미결정 사항

- 거래 수수료·보호/자본 사용 비용의 기준, 요율, 선납·발생·환급, 비용 부족 처리, 프로토콜/볼트 귀속.
- 관측 확정과 정정 마감, 정상 만기 정산 검증 대기시간.
- LP 구간 도중 장애가 발생했을 때 유효 처리시간을 재시작할지 누적할지, 지연 복구·신규 시장의 정확한 상태 전이.
- 빠른 시연용 별도 주기와 구현 스택. 실데이터의 EWMA를 임의로 가속하는 승인이 아니다.

## 근거와 적용 범위

- 사용자 직접 승인: “추천대로 픽스할게”. 직전 추천은 주간 공통 만기·30분 개설 마감·지급 확정 및 유효 NAV 이후 최소 15분 LP·조건 확인 후 재개·자동 갱신 없음·정기 및 초기 LP 운영이었다.
- 직전 비교와 시간 예시는 [핵심 Working](<../20_Working/관심 선택 제품의 핵심 결정과 비교 기준.md>)에 보존한다. 영구 메시지 링크/fragment ID는 제공되지 않았다.
- 테스트넷 MVP 설계 채택이며 코드 구현·경제 검증·메인넷 배포 승인이 아니다. 프로토콜 시간 규칙으로 기록하며 개인 일정이나 자동 실행 작업을 생성하지 않는다.
