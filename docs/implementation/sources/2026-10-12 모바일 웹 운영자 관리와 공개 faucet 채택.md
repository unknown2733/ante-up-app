# 모바일 웹 운영자 관리와 공개 faucet 채택

## 결정

- 모바일은 모바일 웹으로 구현한다. 추가 설치형 앱은 만들지 않는다. Seeker 실기기에서 사용하는 방향을 모바일 웹 접속·지갑 연결·서명·기록 공유 흐름으로 구체화한다.
- MVP의 운영 제어는 운영자가 모두 담당할 수 있도록 구현한다. 분산 거버넌스나 외부 운영자의 참여를 선행 조건으로 요구하지 않는다. 구체 관리자 액션과 계정 권한은 구현 명세로 작성한다.
- 테스트 자산은 앱 내부 faucet에서 받을 수 있게 한다. 공개 방문자가 초대/수동 지급 요청 없이 이용을 시작할 수 있는 흐름을 채택한다. 기존 tUSD 및 Devnet 방향을 유지한다.
- 공개·공유 범위는 Fomo의 실제 제공 기능을 확인하고 참고해 구체화한다. 이번 지시는 참고 조사 방향이며 Fomo의 모든 공개 범위·피드·팔로우·알림·포지션 공개를 그대로 채택한 것이 아니다.

## 범위와 영향

후속 [무료 공개 프로필과 진행 중 선택 공개](<2026-10-12 무료 공개 프로필과 진행 중 선택 공개 채택.md>)에서 무료 공개 범위를 채택하고 Pro/LP 공개·전체 소셜 피드를 유보했다. 이 문서의 나머지 결정은 유지한다.

운영 권한을 한 주체가 담당한다는 선택과 역할별 키는 구분한다. 기존 가격 게시 키·SAS 발급 키 분리는 유지하며 사용자 지갑의 서명을 운영자가 대신할 수 있다고 해석하지 않는다. 기존 완료 기록·정산 보존 원칙을 임의 수정하거나 실제 Arweave 원자료를 삭제하는 기능을 승인한 것으로 확대하지 않는다. 운영자 중심 제어의 세부 액션과 프로그램 업그레이드/설정 권한, 기존 계약에 대한 적용 경계는 구현 명세에 명시한다. 관리자 통제를 탈중앙 운영이나 운영자 개입 불가능성으로 설명하지 않는다.

faucet의 지급량·재요청 간격·전체 지급 한도는 미정이다. tUSD와 네트워크 수수료용 Devnet SOL을 구분하며, SOL 소액 지급 또는 수수료 대납 중 실제 신규 방문자 흐름을 만족하는 방식을 구현 명세에서 정한다. faucet 발행 가능성을 볼트 담보 잔고로 계산하지 않고 실제 예치/출연 시에만 반영한다.

설치형 앱·스토어 배포는 이번 MVP 구현 범위에서 제외한다. 모바일 웹 지갑 연동은 브라우저/지갑 조합을 실기기에서 검증해야 하며 모든 모바일 환경 호환을 확인한 것은 아니다. 서버·컨트랙트·프런트 구현, 실제 faucet 지급과 배포는 이번 작업에서 실행하지 않았다.

## 근거

사용자 직접 발언: “모바일은 모바일 웹으로 진행할거고, 추가적으로 설치형으로는 만들지 않을거야. 공개공유범위는 fomo의 경우에 어떻게 되어있는지 확인하고 참고하는걸로 할거야. 일단 mvp에서는 운영자가 모두 컨트롤 할 수 있도록 구현할거고 테스트 자산은 앱 내부에서 faucet에서 받을 수 있도록 해서 공개방문자가 바로 사용해볼 수 있도록 하자 하나씩 확인해봐”. 영구 메시지 링크와 fragment ID는 제공되지 않았다.
