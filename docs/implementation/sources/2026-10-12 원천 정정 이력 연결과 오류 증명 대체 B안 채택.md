# 원천 정정 이력 연결과 오류 증명 대체 B안 채택

## 결정

테스트넷 MVP의 무료 기록과 SAS에 대해 원천 정정 B안과 계산·발급 오류 B안을 채택한다. 역사적 기록의 보존과 현재 증명의 유효성을 구분한다.

### 원천 정정 B: 당시 결과 유지와 정정 이력 연결

- 당시 사용한 입력과 규칙대로 올바르게 계산했다면 원천 소스가 나중에 수정해도 종료 결과와 증명을 유지한다. 관련 관측의 정정 사실과 버전 이력을 연결한다.
- 대표 성과는 당시 확정 결과다. 수정 데이터의 참고 성과를 기본 화면에 추가할 필요는 없다.
- 기존 관측 구간 끝부터 24시간 일반 정정 정책과 완료 거래·정산 보존은 유지한다. 기한 밖 수정은 참고 이력으로 구분하고 일반 정정으로 소급 적용하지 않는다.
- 예: h 1.25에서 1.50으로 종료한 +20%는 유지한다. 원천 수정 후 종료 h가 1.48로 재계산되더라도 +18.4%로 종료 결과를 교체하지 않고 정정 이력을 연결한다. 예시 수치는 가상이다.

### 계산·발급 오류 B: 기존 증명 무효 표시와 수정 증명 연결

- 발급 전에 오류를 발견하면 발급을 보류하고 올바른 내용과 근거가 준비된 뒤 발급한다.
- 발급 후 오류를 발견하면 원 기록과 기존 증명을 보존하면서 오류 증명의 무효 상태를 먼저 게시한다. 검증 가능한 정정 기록을 추가하고 대체 증명을 연결한다.
- 원 기록 +20%, SAS +200% 오류이면 원 기록은 그대로 두고 +200% 증명을 무효 표시한 뒤 +20% SAS로 대체한다.
- 계산 버그로 원 기록에도 +200%가 저장됐다면 원 기록을 덮어쓰지 않는다. 같은 입력·당시 정한 산식에 따른 올바른 +20%와 원 기록/오류 사유를 정정 기록으로 연결한다. 수정 SAS가 원 기록 자체에 +20%가 저장돼 있었다고 주장하지 않도록 한다.
- 근거가 부족하면 새 점수를 만들지 않고 성과 검증 불가로 남긴다. 선택·종료 사실과 성과 계산의 유효성은 구분한다.
- 수정 근거의 Arweave 보관과 기존 필수 자료 전체 내용 검증·체인 포함·20확인을 충족한 뒤 수정 SAS를 발급한다. 그동안 오류 확인·수정 증명 대기로 표시한다.
- 계산·발급 오류에는 원천 데이터의 24시간 일반 정정 마감을 적용하지 않는다.

### 권한과 검증 상태

- 기존 운영자 증명 관리 권한으로 처리하며 대상 기록/기존 SAS ID, 오류 종류·사유, 근거 해시, 정정 시각, 처리 권한자, 대체 SAS ID 또는 대기 상태를 남긴다.
- 기록별 증명 상태와 대체 연결을 자체 프로그램에 온체인으로 두고 검증 화면에서 SAS와 함께 확인한다. 같은 결과의 정상 대표 증명을 식별하고 과거 버전은 이력으로 보존한다.
- 사용자에게 불리한 점수를 지우거나 운영자가 진입·종료 시점을 바꾸는 권한을 부여하지 않는다. SAS의 자체 기능만으로 이 제품 정책이 자동 구현되는 것으로 간주하지 않는다.

## 범위와 영향

무료 기록·증명의 정확성 처리다. 완료된 금전 거래·정산·지급액을 자동으로 소급 변경할 권한은 포함하지 않는다. 가격 계산 오류가 금전 모듈에 영향을 주면 별도 사고 조사와 거래 통제가 필요하다.

새 증명 상태/정정 연결 스키마와 권한 검사는 구현 명세로 남는다. 공개·공유 범위는 다음 선택이며 이번 채택에 포함하지 않는다. 실제 구현·발급·업로드는 미실행이다. 근거 재현이나 대체 연결 검증이 불가능하면 발급을 보류하고 설계를 재검토한다.

## 근거

사용자 직접 발언: “좋아. 그러면 원천 정정 B안이랑 계산·발급 오류 B안으로 픽스하고 기록해줘. 다음으로 공개·공유 범위를 어떻게 설정할지 선택지랑 예시로 정리해보자.” 직전 응답의 두 B안과 최소 규칙을 승인했다. 영구 메시지 링크·fragment ID는 제공되지 않았다.
