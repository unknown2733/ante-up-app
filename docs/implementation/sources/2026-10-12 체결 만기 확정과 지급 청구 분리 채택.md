# 체결 만기 확정과 지급 청구 분리 채택

## 맥락

[관측 U1·정정 C2](<2026-10-12 최초 검증 관측 사용과 24시간 정정 마감 채택.md>), 주간 만기, 장애24시간 비상 정산, 미지급 예약과 LP N3에 체결·정산의 종료 시점을 연결한다.

## 결정

### 사용자 직접 종료

- 유효한 게시 버전과 실행 조건으로 체결한 가격·지급액을 고정한다. 추가 데이터 정정 대기를 두지 않고 완료 체결을 재정산하지 않는다.
- confirmed에서는 체결 확인 중, finalized 확인 후 최종 완료로 표시한다. 체인 확정을 기다리며 가격·보유기간·비용을 다시 계산하지 않는다. 계약 종료 시각은 성공적으로 실행된 거래에 기록한다.
- 만기 전 요청이라도 실행이 만기 이후면 중도 종료가 아니라 원만기 정산 경로로 처리한다. 견적의 구체 유효기간·가격 허용범위·버전 검사 세부는 구현 명세다.

### 정상 만기: 15분 검증

- 원만기T에 가격 노출·시간 비용을 종료하고 T까지 발생한 활동만으로 평가한다.
- T+15분 전까지 검증·수용한 자료의 마지막 유효 버전을 공통 정산 입력으로 고정한다. 각 버킷의 일반 정정 마감도 적용한다.
- 같은 시장·만기의 모든 포지션에 동일한 정산 가격/버전을 적용한다. 사용자별 진입 조건과 비용에 따라 지급액은 다르다.
- 작업 지연으로 입력 마감을 늦추거나 만기 이후 활동을 포함하지 않는다. 15분은 송금 완료 시각의 보장이 아니다.

### 자료 지연·비상 정산

- T+15분에 자료가 부족하면 미확정/복구 대기로 유지한다. 기존 장애 기한 안에서 만기 평가에 필요한 자료를 처음 완전히 복원·검증한 버전으로 확정하며 추가15분을 기다리지 않는다.
- 복구 시점 현재 가격을 사용하지 않고 원만기T의 가격을 복원한다. 일반 정정 마감·결측 보충 구분을 유지한다.
- 기존 장애 기산점부터24시간 내 미복구면 장애 직전 마지막 검증 가격·버전으로 공통 비상 정산한다. 새로운15분/24시간 대기를 추가하지 않는다. 기한과 복구의 경합·중복 실행은 구현에서 단일 상태 전이로 처리해야 한다.

### 지급과 LP 처리

- 직접 종료는 가능한 경우 체결과 지급을 한 거래에서 처리한다. 주간·비상 정산은 지급액 확정과 실제 송금/청구를 분리한다.
- 미지급 정산금·환급금은 지급까지 부채/예약에 유지하고 한 번만 지급한다. 모든 사용자의 청구 완료를 LP 개방의 필수 조건으로 두지 않는다.
- 모든 Pro 지급액 확정, 미지급 의무 반영, 현재 유효 가격/NAV 확보 이후 최소15분 LP 구간을 시작한다. 정산 확정과 현재 현물 가격 복구를 구분한다.
- LP 구간 중 데이터 장애면 중단하고 복구·현재NAV 확인 후 연속15분을 다시 제공한다. 다음 Pro 개방이 지연될 수 있다.

## 이유와 영향

사용자의 중도 종료는 즉시 실행 흐름을 유지하고 예정 만기에는 공통 검증 기회를 둔다. 청구 순서로 정산가격이 달라지지 않고 개별 미청구 때문에 LP가 영구 대기하지 않도록 한다. 미지급 부채를 삭제하거나 기존 의무를 줄이는 결정은 아니다.

다음은 EWMA·졸업·주간 이월·정정·고정 가격 상한의 최종 연결이다. 가격 연결 후보는 이번 승인에 포함하지 않는다. 운영 배치 크기·keeper/청구 권한·반올림·시각/버전 증빙 세부는 구현 명세다. 재검토 조건은15분/연속LP 운영이 실측 데이터 지연으로 과도하게 지연되거나 상태 전이에 모순이 발견되는 경우다.
