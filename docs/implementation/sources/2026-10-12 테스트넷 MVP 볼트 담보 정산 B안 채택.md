# 테스트넷 MVP 볼트 담보 정산 B안 채택

## 맥락

기존 풀 기반 보호형 방향에서 구현 전 선택을 테스트넷 MVP 범위로 좁힌다. 실제 LP 차입·재구성·복구까지 구현하는 A, 볼트가 담보를 확보하고 명시된 계약식으로 정산하는 B, 서버 계산 중심 시뮬레이션 C를 비교했다. 이번 결정은 테스트넷 구현 범위이며 메인넷 경제 구조의 최종 승인이나 구현 완료가 아니다.

## 결정

> 테스트넷 MVP는 실제 외부 데이터와 테스트 자산을 사용하는 볼트 담보·정산 구조로 구현한다. 본딩커브·졸업·칩 거래·보호형 롱숏·LP 예치와 출금·기록을 연결한다. 보호 범위와 지급 책임은 명시적인 계약식과 담보 조건으로 정한다. LP 차입·재구성·복구 메커니즘은 이번 MVP에 포함하지 않으며 해당 방식의 검증을 완료했다고 간주하지 않는다.

- 키워드별 볼트가 포지션에 필요한 지급 여력을 확보하고 진입·유지·종료·비용·정산·자산 해제를 처리하는 B안을 채택한다.
- 실제 Counts 수집과 EWMA, 테스트 자산의 온체인 이동·포지션·볼트 회계를 연결하는 방향이다. 상세 데이터 게시·실행 경계는 후속 명세다.
- 무료·금전 칩과 Pro 모드, 영어 키워드 자유 등록, 본딩커브·졸업, 초기 볼트 자본 잠금, 외부 LP, 롱숏, MVP 포지션 부분 종료 미지원 방향을 유지한다.
- 최대 진입5배·성장률 상한+400%의 기존 초기 설계 기준을 유지하되, 최종 가격식·적용 위치·양방향 지급식·담보 책임의 범위는 미정이다.
- B의 보호 근거는 정해진 계약 권리와 확보한 담보다. InfinityPools 계열의 실제 LP 복구를 구현했다고 표현하지 않는다. 보호의 정의·최대 지급 책임을 다음 단계에서 명세해야 한다.
- 메인넷 사용·실자금 거래·특정 클러스터/프로그램 채택·유료 API 지출을 승인하는 결정이 아니다.

## 이유

전체 사용자 흐름과 실제 테스트 자산 회계를 연결해 데이터→가격→손익, 반복 거래·쏠림·동시 종료·LP 출금의 영향을 관찰한다. LP 재구성 메커니즘의 성립 여부를 먼저 해결해야 하는 A안과 구현 범위를 구분한다.

## 검토한 대안

- A: 실제 LP 차입·재구성·복구까지 구현. 이번 테스트넷 MVP에서는 제외하고 연구 이력은 보존한다.
- C: 서버에서 계산·화면·기록만 시뮬레이션. 온체인 자산 확보·지급·지분 회계까지 연결하기 위해 B를 선택했다.

## 영향

- [풀 기반 보호형 방향](<2026-10-09 풀 기반 보호형 거래 설계 방향.md>)과 [키워드별 볼트](<2026-10-10 키워드별 프로토콜 운영 볼트.md>)의 적용을 테스트넷 MVP 범위에서 부분 조정한다. 기존 결정 전체를 superseded로 바꾸지 않는다. 특히 기존 '직접 현금 상대방으로 미리 확정하지 않는다'는 유보를 이번 MVP에 한해 계약식 기반 볼트 정산으로 구체화한다. 무제한 선형 지급을 채택하지 않는다.
- 다음 결정: 무료 칩·금전 칩·Pro 포지션·LP 지분 각각의 보유·종료·양도·수익 권리. 현재 권리 선택지와 예시는 미채택 제안이다.
- 이후: 계산식→최소 볼트 회계→데이터 게시/확정→스택/화면. 일반 정정24시간·만기 검증15분은 여전히 미채택이다.
- 재검토 조건: 지급 책임을 정의할 수 없거나 담보/지분 회계의 일관성을 확보할 수 없을 때. 테스트 결과를 메인넷 안전성 증거로 확대하지 않는다.
- 이번 작업은 문서화이며 구현·배포·API 실행은 수행하지 않는다.

## 근거

- 결정 주체: 사용자 직접 선택.
- 2026-10-12 현재 대화 직접 인용: “좋아. 그러면 테스트넷 MVP는 B안으로 일단 픽스하고 기록해줘. 다음으로 무료 칩·금전 칩·Pro 포지션·LP 지분이 각각 어떤 권리를 갖는지 선택지랑 예시로 정리해보자.”
- 승인 대상은 직전 답변의 볼트 담보·정산 B안과 그 테스트넷 한정 범위다. 영구 메시지 링크·fragment ID는 제공되지 않았다.
