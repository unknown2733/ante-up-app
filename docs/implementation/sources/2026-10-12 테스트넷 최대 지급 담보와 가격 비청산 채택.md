# 테스트넷 최대 지급 담보와 가격 비청산 채택

## 맥락

[테스트넷 볼트 정산 B안](<2026-10-12 테스트넷 MVP 볼트 담보 정산 B안 채택.md>)과 [네 권리 구분](<2026-10-12 테스트넷 네 종류의 사용자 권리 채택.md>)에 실제 매도·지급 규칙을 연결한다. 실제 외부 데이터와 테스트 결제 자산을 전제하며 메인넷 안전성·지속 가능성을 승인하지 않는다.

## 결정

- 졸업 이후 금전 칩은 유효한 지수 연동 기준가격P에서 수량q에 대해 q*P-거래비용으로 매도하는 현물A를 채택한다. 본딩커브 단계의 매매는 별도 커브 규칙을 유지한다.
- 외부 보유·환매 대상 토큰 전체에 대해 가격 상한에서의 최대 지급 재원을 실제 결제 자산으로 사전에 확보한다. 졸업 자금만으로 충족된다고 가정하지 않는다. 이후 추가 판매/재판매에서도 증가 의무를 확보하고 지갑 간 전송으로 의무를 해제하지 않는다.
- Pro A: C=담보, L=진입 레버리지, N=C*L, P0>0=진입가격, P=종료 평가가격, d=롱+1/숏-1일 때 비용 전 총지급 R=max(0,C+d*N*(P/P0-1)). R은 담보 반환을 포함하며 사용자 순이익이 아니다.
- 거래 손실은 담보까지이고 추가 개인 채무를 만들지 않는다. 별도 납부 비용은 추가 부담이며 원금 보장을 뜻하지 않는다. 비용 별도 납부 예시의 순손익은 R-C-F이고 최종 요율·납부/차감 방식은 후속 명세다.
- 별도 포지션 이익 상한을 추가하지 않는다. 기존 시장별 고정 가격 상한 범위에서 최대 지급을 확보한다. 상한을 매 진입/주간마다 사용자에게 유리하게 새로 리셋하는 규칙은 채택하지 않는다.
- 가격 범위[0,Pmax]에서 롱의 최대 총지급은 C+N*(Pmax/P0-1), 숏은 C+N이다(0<P0<=Pmax). 숏의0은 보수적 수학 경계이며 무효 데이터0을 실제 정산에 사용하는 뜻이 아니다. 최신 EWMA·졸업/주간 앵커와 가격 상한의 최종 연결은 검증해야 한다.
- 약정 기간·비용 조건과 필요한 담보가 유지되는 동안 가격 변화만으로 포지션을 자동 종료하지 않는다. 평가액0에서도 유지하면 이후 회복에 참여할 수 있고 필요한 담보를 해제하지 않는다. 사용자의 전량 종료·원래 만기·기존 데이터 장애/비상 정산 규칙은 유지한다.
- 최대 지급을 감당할 자본 범위에서만 신규 거래를 수용한다. 비용 소진 처리·정상 만기/갱신·상세 예약 회계/거래 한도·LP 출금 규칙은 후속이다. 자산 부족 시 기존 권리를 임의로 축소하는 승인이 아니다.

## 이유

테스트넷에서 별도 수익 상한이나 임의 할인 없이 가격·손익 경험을 연결하면서 최대 지급액을 명시한다. 높은 자본 점유를 수용하고 반복 거래의 자본 감소를 관찰한다.

## 검토한 대안

- 현물의 볼트 상태별 할인·수량 견적, 지수와 괴리를 허용한 시장가격: 이번 추천 조합에 포함하지 않았다.
- Pro 별도 지급 상한300·담보 일부 최소 반환50: 비교 예시이며 채택하지 않았다.
- 평가액0 자동 종료: 약정 기간 내 가격만으로 자동 종료하지 않는 방향을 선택했다.

## 영향

- 예시 c=10/Pmax=50, 담보100/진입가격10의5배 롱 최대 지급2,100·숏600은 계산 예시다. 모든 시장의 공통 상한·담보액·요율을 확정하지 않는다.
- 기존 부분 종료 미지원·테스트넷 한정·지표 및 데이터 장애 규칙 유지. 담보 예약액은 이익/NAV와 같지 않으며 LP 출금 권리와 별도 계산이 필요하다.
- 다음은 같은 볼트에서 현물·Pro·LP의 자산 중복 사용을 방지할 예약 회계와 거래 한도다. 포지션별 예약 단순합·상계 금지·출금 부족 시 거절 등은 다음 제안으로 구분한다.
- 재검토 조건: 가격 상한/공급량·계약 지급식·실제 결제자산의 불일치 또는 구현 불가능성이 확인될 때. 구현·배포·유료 API 실행은 이번 기록에 포함하지 않는다.

## 근거

- 사용자 직접 선택,2026-10-12 현재 대화: “좋아. 그러면 추천한 조합으로 일단 픽스하고 기록해줘. 다음으로 현물 매도랑 Pro 정산, LP 출금이 같은 볼트 자산을 사용할 때 담보를 어떻게 예약하고 거래 한도를 계산할지 두쫀쿠 예시로 정리해보자.”
- 직전 추천 현물A·Pro A·기간/비용 조건 내 가격만으로 자동 종료하지 않음·최대 지급 자본 범위 신규 거래를 승인한 것으로 기록한다. 예시 수치나 후속 회계 정책 승인으로 확대하지 않는다. 영구 메시지 링크/fragment ID는 미제공이다.
