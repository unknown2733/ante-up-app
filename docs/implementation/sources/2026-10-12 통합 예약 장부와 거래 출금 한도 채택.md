# 통합 예약 장부와 거래 출금 한도 채택

## 맥락

[최대 지급 담보와 가격 비청산](<2026-10-12 테스트넷 최대 지급 담보와 가격 비청산 채택.md>)을 테스트넷 볼트의 장부와 거래 수용 조건으로 연결한다. LP 지분의 평가 방식·손실 순위는 다음 결정으로 남긴다.

## 결정

- 실제 결제 자산 잔고A에 수취한 Pro 담보를 포함한다. 자기 발행 키워드 토큰의 표시가·예상 미래 수수료는A에 포함하지 않는다.
- 현물 예약 Rs=외부 환매 대상 수량Q*고정 최고가격Pmax. Pro 예약 Rp=각 열린 포지션 최대 총지급액M의 합. 롱숏/현물 간 상계로 예약을 줄이지 않는다.
- 환급 가능한 미경과 선납금·외부에 귀속된 비용·확정 후 미지급 청구 등은 기타 예약H로 구분한다. 같은 의무는 한 번만 계산한다. 사용자 담보는A와 담보 포함M에 이미 반영되므로 다시 차감하지 않는다.
- 가용F=A-Rs-Rp-H-B로 계산한다. B는 별도로 정할 운영 버퍼이며 구체 수치/비율을 이번에 선택하지 않는다. 정상 거래 후F>=0을 유지한다. 가용F는 NAV나 회계 이익이 아니다.
- 신규 Pro는 담보C를 받은 뒤M을 예약하고, 신규 현물 판매는 대금과 늘어난 외부 수량을 함께 반영한다. 비용 제외시 추가 여력 소모는 각각M-C와 q*(Pmax-P)다.
- 신규 거래와 LP 출금은 실행 후에도 기존 예약을 유지할 때만 수용한다. 화면 견적이 여력을 선점하지 않으며 실행 시 최신 상태로 재검사한다. 잔고·권리·예약·지분 갱신을 원자적으로 처리한다.
- 기존 현물 매도/Pro 종료는 해당 예약으로 이행하고 잔여 예약을 해제한다. 단순히F가작다는 이유로 이미 확보한 종료 대금을 막지 않는다. 기존 데이터 장애·계약 조건은 유지한다.
- 가격 갱신이나0평가만으로 회복 가능한 포지션의 예약을 줄이지 않는다. 토큰 지갑 전송으로 현물 예약을 해제하지 않는다.
- 정산과 송금이 나뉘면 지급액을 별도 미지급 예약으로 옮겨 실제 지급까지 유지한다. 종료 상태만으로 지급할 돈을 가용으로 풀지 않는다.
- LP 출금은 해당 사용자의 지분 상환권과 가용F를 함께 검사한다. MVP는 요청액 전체를 처리할 수 있을 때 실행하며 부족하면 거절하고 가능한 금액/재요청을 안내한다. 자동 부분출금·대기열은 채택하지 않았다. 초기 잠금 지분은 개인 출금 대상에서 제외한다.
- 실제 수취 비용도 환급/외부 귀속 의무를 먼저 유보한다. 발생했고 볼트에 귀속된 수입만 가용 증가에 반영한다. 수취·수익 인식·외부 배분을 중복 계산하지 않는다.

## 이유

서로 다른 시점에 발생할 현물 매도·롱숏 정산·LP 출금이 같은 자산을 중복 사용하지 않도록 한다. 자본 효율보다 단순하고 확인 가능한 최대 지급 예약을 우선한다.

## 검토한 대안

- 현재 롱숏 손익을 상계해 담보 절감: 개별 사용자의 선택적 종료 시점이 달라 이번 MVP에서는 사용하지 않는다.
- 현재 가격의 지급액만 예약: 이미 선택한 최고가격/회복 권리를 충분히 뒷받침하지 못한다.
- LP 출금 대기열/자동 부분처리: 이번 전액 실행·부족 시 거절 범위 밖이다.

## 영향

- 잔고1만·가격상한50·가용2,500·현물62.5개/롱담보125/숏담보500 등은 예시이며 고정 운영 한도가 아니다. 새 지표·가격/비용·잔고로 한도를 계산해야 한다.
- 예약 해제는 이익이 아니고 LP 지분 가격은 별도 순자산 평가로 정한다. 현재 종료액과 회복 가능한 보호 계약의 가치도 같다고 확정하지 않는다.
- 다음 검토: LP 평가 기준, 초기 잠금 자본/외부 LP 손익 순위. 운영 버퍼·요율·정상 만기/갱신·비용 소진·체결 공정성 세부는 미정이다.
- 재검토 조건: 가격 범위·공급량·계약 지급/비용이 예약 가정과 달라지거나 장부 불일치가 확인될 때. 음수 가용을0으로 감추거나 기존 지급권을 임의 축소하는 승인이 아니다.
- 문서 기록이며 코드·유료 호출·배포·실거래는 실행하지 않는다.

## 근거

- 사용자 직접 선택,2026-10-12 현재 대화: “좋아. 그러면 추천한 예약 방식이랑 거래·출금 한도로 일단 픽스하고 기록해줘. 다음으로 LP 지분 가격을 어떤 순자산 기준으로 계산할지랑 초기 잠금 자본과 외부 LP가 손실을 어떤 순서로 부담할지 선택지랑 두쫀쿠 예시로 정리해보자.”
- 직전 추천의 상계 없는 최대 예약·신규/출금 가용 검사·기존 지급 이행·원자적 변경을 승인한 것으로 기록한다. NAV/손실 순위·다음 제안의 LP 거래 시점 제한은 승인 범위가 아니다. 영구 메시지 링크/fragment ID는 미제공이다.
