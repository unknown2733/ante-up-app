# Fixture API and guarded live boundary

Requires Node 24. Run `npm test --prefix services/api` and `npm start --prefix services/api`. The server binds only to `127.0.0.1:8787` by default; `PORT` changes the port. Try `GET http://127.0.0.1:8787/v1/markets` and `GET /v1/leaderboard?period=7d`.

The default server returns `mode: fixture` in every response envelope. Fixture IDs are synthetic. Even a finalized-looking fixture snapshot has `price.executable: false`, and quote/prepare return `kind: notExecutable` with no transaction bytes. The local server has no chain RPC, faucet, paid data, upload, or SAS path. `POST /v1/faucet/claims` returns `PENDING_CONFIRMATION` and never pays.

`createApp({mode})` requires explicitly matching live adapters for `localnet` or `devnet`; the fixture adapter cannot be relabeled. A signed challenge for a different cluster is rejected in those modes. The fixture returns `notExecutable`. The explicit live factory below prepares Free transactions without a server signer. Prepared transaction validation binds wallet, cluster, program, request, action, record, block height, and a deadline of at most 30 seconds.

## Explicit localnet/devnet runtime

`createLiveApp` in `src/live.ts` wires the finalized SQLite projection, B account codecs and Free instruction builders, a Kit blockhash reader, a hashed bearer session store, durable operations, and a read-only chain receipt verifier. It accepts injected account, blockhash, and receipt readers for deterministic tests. The process entrypoint remains fixture by default. To start live mode, set `ANTE_UP_MODE=localnet` or `devnet`, `ANTE_UP_PROGRAM_ID`, `ANTE_UP_RPC_URL`, `ANTE_UP_INDEX_DB`, and `ANTE_UP_MARKETS_PATH` pointing to a JSON array of `{address,seedHex,keyword,aliases}` market registry entries. The indexer must poll the same database separately. No wallet secret or server signer is used.

`POST /v1/auth` then `POST /v1/auth/session` exchanges one signed challenge for a wallet and cluster bound bearer token. Only the SHA-256 token hash is stored, with a 15-minute expiry. Bearer authentication protects prepare, submit, and operation lookup. `POST /v1/transactions/prepare` returns wallet-signable unsigned base64 for `openFree` and `closeFree` when the finalized market and global admission checks permit it. Free entry does not require valid numeric data; missing data may produce N/A. The server never submits a transaction. `POST /v1/operations/:requestId/submit` records a claimed signature and verifies actual RPC transaction bytes, wallet signature, and prepared message before confirmed/finalized status. A missing RPC receipt remains `UNKNOWN`. GET operation lookup can inspect up to 20 finalized signatures at the record PDA and attach only an exact signed message match. Money actions and `/v1/quotes` remain non-executable.

Read routes: `/v1/markets`, `/v1/markets/:id`, `/v1/markets/:id/snapshots`, `/v1/records/:id`, `/v1/proofs/:proofId`, `/v1/profiles/:wallet`, `/v1/leaderboard?period=7d|all`, `/v1/operations/:requestId`. Lists support `limit` (1..100) and decimal offset `cursor`. Unknown proof IDs return `data: null`. The profile response supplies the shared `PublicProfile.openPreviews` field, whose reference values come from the latest finalized fixture snapshot, not settled returns. They become `UNAVAILABLE` when the snapshot is stale, missing, or has no denominator.

`POST /v1/auth` accepts `{wallet,cluster}` and returns a nonce, expiry, and the exact domain-separated message. `x-ante-nonce` and `x-ante-signature` (base64 Ed25519 signature by that Solana wallet) are required for quotes, prepare, and operation reads. A nonce is consumed once. Admin actions additionally need an `AdminAuthorizer`; the fixture default denies all and logs attempts in memory. Executable quotes need the contract's 30-second TTL when a live adapter is added; fixture quote and prepare return only `kind: notExecutable`. They still demand signatures so callers can exercise the boundary without implying execution.

## Persistent adapter plan

`migrations/001_init.sql` chooses SQLite with WAL, one database per environment, and a single writer transaction for event upsert plus read-model update. No cloud DB product or host path is embedded. Store `cluster+program_id+signature+event_index` as the unique chain event key and `(wallet,action,request_id)` as the operation key. Re-read finalized chain state before replacing a provisional view. A process crash after submission leaves `UNKNOWN`; reconcile signature and contract ID before another submission. `worker_attempts` needs an atomic lease and durable UNKNOWN receipt. Nonces and admin audit also need database-backed adapters before network exposure. The current in-memory adapter demonstrates semantics, not restart persistence or multi-process atomicity.

Snapshot and free-record read models are chain-derived caches. Indexer replay must not overwrite finalized records with confirmed events. Free records use one current projection per `(cluster,programId,recordId)` and can replay through a transaction cursor; ambiguous same-slot ordering fails closed. Calculation-error corrections need immutable history and verified replacement before releasing a held wallet. The production SQLite adapter, B event layout/IDL, B's chosen atomic on-chain admission counters, and real transaction builder are pending integration.
# Financial API boundary

The shared wire DTO is `contracts/financial.ts`. The `/v1/financial/*` routes require the existing wallet challenge/session. `GET /portfolio` is owner-only; `GET /vaults/:marketId` is a public aggregate. A `FinancialReader` must return finalized chain-backed data with matching cluster, program, wallet, and slot. Without that reader, these reads return `DATA_NOT_READY`, and quotes return `kind: notExecutable`.

`POST /v1/financial/quotes` validates canonical action-specific intent, uses a finalized market and snapshot for price-dependent actions, and stores the immutable quote in SQLite for 30 seconds. Retrying the same request ID returns that quote; changing intent or network fails. Claim quotes are checked against fixed claim state by the chain adapter and do not depend on the current market price. Quotes return `notExecutable` unless both a chain reader and B's financial transaction adapter are configured. `POST /v1/financial/transactions/prepare` takes only `{wallet,requestId,quoteId}`. A configured adapter must check every generated instruction, account, discriminator, and data field before prepared bytes are persisted. No production B adapter is wired yet, so the route remains `notExecutable` in the default runtime. Existing Free routes remain executable under their existing safeguards.

Financial preparations are stored separately from Free records, with an explicit discovery address for bounded lost-response recovery. A financial prepared DTO has no Free `recordId`. Submission and reconciliation compare the signed transaction's exact message bytes and verify the wallet signature; an RPC miss remains `UNKNOWN`. The SQLite schema adds `operation_kind` and `discovery_address` to existing stores on startup.

The API stores quote/operation metadata, never asset balances as spendable truth. The financial adapter must enforce chain account ownership, token mints, u64 amounts, reservations, faucet allowance, LP window, claim owner/status, settlement input, and quote version at execution. No financial transaction is broadcast by this service.
