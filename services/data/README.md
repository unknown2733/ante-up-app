# C fixture data pipeline

Run `node --test services/data/index.test.mjs` from the repository root. No package install or paid API call is needed.

`buildQuery()` accepts explicit English phrases/hashtags only and returns one parenthesized OR query with `lang:en -is:retweet`. The X Counts docs say OR grouping avoids duplicate addition and quote matches only newly written quote text; this fixture builder does not prove live matching. The query and aliases must be fixed at registration and versioned externally. [X query guide](https://docs.x.com/x-api/posts/counts/integrate/build-a-query).

`ingestCounts()` requires the caller to supply the request range and `granularity: 'minute'`; the official sample response does **not** echo granularity. Normal request ranges are five minutes. A delayed worker may fetch multiple contiguous five-minute ranges in one bounded request (up to the seven-day recent horizon); this counts as one recovery observation. `historical: true` permits up to 28 days for initial backfill. Every omitted interval becomes `missing`, while an explicit `tweet_count: 0` becomes a valid zero. It returns one 60-second Observation per interval with a SHA-256 of the canonical raw response. `FileRawResponseRepository` preserves the raw response by content hash before evidence processing; production needs a durable, backed-up repository and request metadata next to it. [X Counts response and granularity](https://docs.x.com/x-api/posts/counts/introduction).

`replay()` is an as-of calculation: it includes only versions received and validated by `computedAt`. `replayLatest()` is the deliberately named entry point for a current analytical recomputation; callers must not use that result to rewrite an old finalized trade. The selector classifies initial history, first observations, gap fills, and corrections. A valid count changing to another value is accepted only when validated before `bucketEnd + 86400`; filling a missing bucket remains possible later after recovery validation. Late ordinary corrections are audited without applying them. It reseeds from the oldest complete day and replays all subsequent minutes. A gap stops `dataThrough` even when later buckets exist. `computedAt` never replaces `dataThrough`. Returned `usedVersions` records each selected bucket revision and raw hash for durable trade/settlement references.

The first-day seed is the arithmetic mean of its 1,440 daily-rate samples: `sum(first-day minute counts) * Q12`. For each later minute, `X = minuteCount * 1440 * Q12`, `alphaQ12 = 160437865`, and `S_next = floor((S_prev*(Q12-alphaQ12) + X*alphaQ12 + Q12/2)/Q12)`. The alpha is the nearest integer to `(1 - 2^(-1/4320))*1e12`, for a three-day half-life. Each step rounds once to nearest Q12 integer, ties upward. `S_7d` is the state at exactly 10,080 minutes earlier, not an average or a separately rounded ratio. If all daily-rate inputs and seed lie in `[0,M]`, the absolute Q12 conversion error against the real-alpha recurrence is bounded by approximately `3.12e-9*(M+1)` daily counts after any number of steps; this includes alpha quantization and the at-most-half-Q12-unit rounding each step. This bound is conditional on `M`, not a blanket bound for unbounded counts.

`replay()` returns a `SnapshotCandidate` with `queryHash` and `admission`, plus canonical payload hash, correction audit, and operational `RecoveryState`. Formula version is fixed to `h3-d7-q12-v1`; Q12 outputs must fit u64. With valid history, 10-minute age gives `OUTAGE`, and the incident starts exactly at `dataThrough + 600`; its 24-hour deadline is held across partial recovery. Actual low activity under 100 daily counts is `LOW_ACTIVITY`; a zero D7 denominator is `PREPARING / INVALID_DENOMINATOR`.

DataStatus describes whether the calculation is valid. `admission` separately controls new trades: after a prior low-activity or outage block, a complete valid recovery may allow exits while admission remains `RECOVERING`. One successful **regular 300-second poll batch** with advancing `dataThrough` increments the streak once, regardless of how many minute observations it carried. A second distinct regular batch at least 300 seconds later opens admission. Bootstrap, backfill, repeated IDs, and low/invalid batches do not make two confirmations. Persist the returned `RecoveryState` (including last poll ID/time) and pass it as `prior` after restart. A candidate is never a `PublishedSnapshot`; the chain acceptance path must assign sequence, accepted version, transaction, and finality before quotes use it.

## Counts transport and local scheduler

`live.mjs` builds the documented `/2/tweets/counts/recent` and `/2/tweets/counts/all` URLs with `query`, ISO `start_time`/`end_time`, `granularity=minute`, and bearer authorization. The former handles one 300-second regular batch; the latter handles the authorized 28-day initialization. The query hash is SHA-256 of the exact UTF-8 query text. Tests inject a fake HTTP fetcher; they do not contact X. [X recent Counts quickstart](https://docs.x.com/x-api/posts/counts/quickstart/recent-tweet-counts).

`runInitialArchive()` and `runRegularPoll()` persist an attempted batch and reserve its estimated cost **before** transport. Attempts remain charged after HTTP failure because actual provider billing is not known. A completed or uncertain `REQUESTING` batch is never repeated; a `FAILED` batch retries only after its backoff. The default limits are $10 UTC daily regular collection and $100 combined X collection including initialization, expressed as integer millionths of USD. The product's $150 total also covers storage and infrastructure; it is not all an X allowance. Every call requires a positive operator-provided per-request cost estimate; no fixed X price is assumed. The JSON state and raw response store are single-writer local examples; distributed workers need a transactional budget ledger/lease and budget reconciliation against actual usage.

The 28-day archive follows `meta.next_token`, reserves estimated cost before **each** page request, and stores each raw page plus a canonical composite raw response containing those pages. `PAGING` resumes from the saved token; an uncertain `REQUESTING` never repeats automatically. The 500-page ceiling and combined X budget stop runaway collection. A missing minute stops `dataThrough`; `runGapFill()` refetches the affected 300-second window with a new observation revision and replays as a backfill, without counting it as a regular recovery poll. The CLI selects gap fill when later observations exist. Requests outside the recent Counts window fail closed. Failed regular HTTP attempts retry after 5, 15, then 60 minutes, with each attempt charged conservatively.

`node cli.mjs` fails with `LIVE_X_DISABLED`. The explicit live path is `node cli.mjs --execute` after setting all fields in `.env.example` and `ANTE_UP_ENABLE_PAID_X=yes`. The example has no token or valid cost and is deliberately non-executable. No scheduled process is started by package install. Add `--publish` plus the candidate file, logical market ID, 32-byte market seed, and ignored runtime module to publish. `ANTE_UP_MARKET_ID` must be the actual market PDA in base58; keywords and the 32-byte `register_market` seed are separate registry fields. `npm test` uses fixture HTTP only.

Live collection returns a `calculation` without `sequence` or `candidateHash`, plus an immutable `replayInput`. Its `VALIDATED` state means the Counts batch was processed. `publishSnapshot()` reads the finalized market/config through `createKitPublisherChain()`, fixes the next chain sequence and current config version, replays the stored input, checks query/version and market PDA, creates B's generated instruction, sends through B's Kit runtime, and stores a `PublishedSnapshot` only after a finalized program account and D projection agree. Sequence/config/query are rechecked before sending. A `REQUESTING` or `SUBMITTED` job is reconciled after restart and is not automatically sent twice.

`runLiveCycle()` first reconciles every prior publication job for the market without an X request or transaction resend. If any remains unresolved, it returns `PUBLICATION_PENDING` and does not collect or publish a newer batch. The next cycle can persist the old finalized snapshot and then proceed to a new 300-second batch. A crash in `PREPARED` remains pending for explicit recovery; it does not silently advance the chain sequence.

An invalid Counts response after a successful HTTP read opens a persisted `SOURCE_INVALID` incident. With `--publish`, the same cycle enters `publishSourceInvalidOutage()` and uses the normal generated `publish_snapshot` instruction, Kit sender, and finalized account plus D projection reconciliation. If the process stopped after saving the incident, the next cycle publishes it **before another paid Counts request**. The job takes the next finalized Market sequence, keeps its prior `latestDataThrough` unchanged, sets `dataStatus=OUTAGE` and admission `BLOCKED / DATA_NOT_READY`, and sets both activity fields to `null`. Its evidence hash commits to the incident ID, archived malformed response hash, and finalized chain baseline; it does not add an Observation. A changed baseline fails before sending. While the incident remains open, partial valid polls cannot replace the outage with stale activity numbers. The distinct `SOURCE_INVALID_OUTAGE` replay marker is checked by E against the archived raw response and finalized snapshot; D's existing candidate/account hash checks accept the normal SnapshotCandidate fields. A pending or uncertain send stays pending and is never automatically repeated.

`getSourceInvalidPublicationState()` is C's read-only bridge for API/keeper admission: `LOCAL_BLOCKED` means only the local incident is known, `PENDING` means the publication lacks B account plus D projection finality, and `FINALIZED` includes the matching signature. A shared API/keeper gate should reject new financial actions while this state is unresolved; a local incident alone does not change on-chain state.

`FileCollectionState` stores `{spentByDay,totalSpentMicros,batches,markets}`. Each validated batch includes `rawHash`, `calculation`, and `replayInput`; `markets[marketPda]` carries observations and recovery state. `FileCandidateRepository` stores `{jobs,snapshots}` where `snapshots[marketPda+":"+sequence]` contains `{market,published,replayInput,candidate,candidateHash}`. D's `SqliteEventRepositories.importCandidateFile()` can ingest both `jobs` and `snapshots`; it must pair a candidate with B's finalized snapshot account before reporting publication. These JSON repositories require one writer and persistent, backed-up volumes.

The sparse finalized event creates a resolver ordering dependency: D needs the candidate before C sees D's projection. `getCandidate(marketPda,sequence,payloadHash)` exposes the immutable candidate from a pending or finalized job for **D's event decoder only**. D must combine it with B's finalized Snapshot account and verify the event/account hash. `getPublished()` remains the public finalized-only read. D must not report a pending candidate as a published snapshot.

The ignored publisher runtime module supplies `endpoint`, `cluster`, `programId`, a Kit `publisherSigner` (and optional `feePayer`), plus D's finalized `projection` or `finalizedSnapshots`. The CLI builds B's transport, signer adapter, and generated instruction sender from those values; no custom publisher callback is needed. The server-backed Devnet path is available through `scripts/collect-devnet.mjs`; credentials and runtime state are external to this checkout.

## Historical weekly settlement input

`settlement.mjs` builds one deterministic price input per market PDA and cycle ID. The existing `epoch` argument and journal key mean B's `FinanceMarket.current_cycle`, never a calendar week number. If emergency settlement is followed by a new cycle in the same week with the same maturity, its new `current_cycle` gets a distinct candidate and journal entry. `epochStartedAt` is that cycle's first position open time, supplied by a finalized B/D binding. The module uses the graduation `PriceAnchor` and the exact BigInt `indexPrice()` reference; weekly display anchors never reset `c` or `Pmax`. `evaluateSettlement()` replays observations with `end = original maturity T` and `computedAt = T+900`, so activity after T cannot enter the result. Corrections must have been received and validated by the cutoff; the ordinary per-bucket 24-hour correction rule still applies. The cutoff is inclusive in this technical implementation. The candidate includes the full selected `(bucketStart, revision, rawHash)` list, its hash, activity numerator/denominator, final price, fixed anchor and chain provenance, and the selection instant.

If T+900 has a gap, the builder checks validated arrival instants in order and selects the first complete historical replay before the **existing** outage deadline. It does not use the current market price. If no complete replay exists at that deadline, it uses the last finalized, valid published snapshot before the outage; its market PDA, payload hash, B-derived snapshot PDA, sequence, cluster and program are checked. A 24-hour outage deadline may precede T: an unrecovered epoch becomes emergency eligible at that original deadline without waiting for future T activity. `eligibleAt` is the decision threshold, while `effectiveCloseAt` stops costs at the earlier of T and the emergency deadline. The caller must supply an authoritative persisted outage start, its recovery state, and an exhaustive last-valid-snapshot query. Staleness uses the persisted `dataThrough+600` origin; a separately proven invalid source or denominator can start immediately. An incomplete 28-day history at T+900 is rejected.

`FileSettlementJournal.freeze()` stores a `FROZEN_LOCAL` candidate and hash once per `(cluster, programId, market PDA, epoch)` for a single local writer. Later corrections or retries return the same candidate. `frozenAt` is journal metadata, not in the candidate hash, so worker delay cannot alter the price identity. This module neither sends a `finalizeEpoch` transaction nor makes a public finalized settlement claim. The on-chain graduation anchor, outage timeline, and last valid snapshot reader must be validated by the caller before financial execution.

### Persisted outage incidents

Each `FileCollectionState.markets[marketPda]` now carries an optional `outageTimeline`. An incident has a content-derived `id`, original `startedAt`, nullable `recoveredAt`, and provenance. Stale data records the original `dataThrough+600`; malformed validated-source responses record their raw hash and batch ID; an invalid denominator records the validation instant and evidence hash. Failed HTTP attempts and internal replay errors do not create a source-invalid incident. Repeated invalid responses, partial gap fills, and restarts retain the first onset. Only a validated, complete current replay closes an incident. Older state files with `RecoveryState.outageStartAt` but no timeline can be read as a single stale incident; the next validated replay persists it. Financial execution must rely on a finalized on-chain OUTAGE snapshot or a separately authorized admission gate; the local incident alone is not a chain confirmation.

`settlementInputFromCollection()` reads the saved observations and chooses the original incident that missed its 24-hour deadline or remained active at T+900, bounded by a trusted `epochStartedAt`. It requests a last finalized valid snapshot through an injected read-only B/D reader only when an emergency deadline has arrived. The caller still supplies the finalized graduation anchor, immutable bootstrap `historyStart`, and epoch start from the market/epoch registry. The JSON state is single-writer; D/B must provide durable authoritative event and account reads before financial execution.


## Server-backed Devnet runner

`node scripts/collect-devnet.mjs --execute` performs one due batch and reconciles its finalized account with the real indexer. Add `--initial` only for the first explicitly authorized 28-day archive, or `--follow` for a supervised worker. The runner requires `ANTE_UP_ENABLE_PAID_X=yes` and these file paths:

- `ANTE_UP_RPC_URL_FILE`: server-only Devnet RPC URL.
- `ANTE_UP_PUBLISHER_KEYPAIR_FILE`: server-only publisher keypair; no deployer/admin key is required.
- `X_BEARER_TOKEN_FILE`: server-only X credential.
- `ANTE_UP_COLLECTION_CONFIG`: JSON with `directory`, `marketId` (PDA), `seedHex`, `logicalId`, `expressions`, `queryVersion`, `historyStart`, and positive `estimatedCostMicros` per request.

The market must already be registered. Genesis, publisher authority, market PDA and exact query hash/version are checked before paid collection. The same persistent directory holds the collection journal, immutable raw blobs, candidate journal and SQLite projection. Use a single collector writer per directory; keep other indexers from simultaneously owning its cursor. Preserve this directory across restarts. A conservative local cost reservation is not the provider's actual invoice; review billing separately.

The runner honors five-minute spacing and retry deadlines, preserves recovery-count semantics, and stops on budget errors. It does not enable public admission, issue SAS, configure Arweave, or run the public API/web process.
